## 🚀 Быстрый старт

**Docker (рекомендуется)**

```bash
git clone https://github.com/Dioprii/infosec_training_platform
cd infosec_training_platform
docker compose up -d --build
```

**Без Docker**

```bash
./run.sh      # Linux / macOS
run.bat       # Windows
```

Откройте **http://127.0.0.1:8000**. База создаётся сама в `data/academy.db`.

> После обновления кода пересобирайте образ: `docker compose up -d --build`, затем обновите страницу через Ctrl+F5.

### Демо-данные

Чтобы посмотреть кабинет администратора на готовых данных, выполните локально:

```bash
python manage.py seed-demo
```

Команда создаёт демо-компанию с сотрудниками. Логины и пароль смотрите в `manage.py`.

⚠️ Только для локального показа. Никогда не запускайте `seed-demo` на рабочем сервере: у демо-аккаунтов известный всем пароль.

### Управляющие команды

```bash
python manage.py create-org "Название" "Имя Админа" admin@company.ru   # компания и администратор
python manage.py reset-password user@company.ru                        # новый временный пароль
python manage.py seed-demo                                             # демо-компания
```

### Настройки (`.env`)

Все значения необязательны, по умолчанию проект работает «из коробки». Список переменных с описанием лежит в .env.example. Чтобы изменить настройку, задайте её как переменную окружения (в Docker — в блоке environment файла docker-compose.yml).

| Переменная | Назначение |
|---|---|
| `ACADEMY_DB` | путь к файлу базы SQLite |
| `COOKIE_SECURE` | `1`, когда сайт открыт по HTTPS (обязательно в продакшене) |
| `TRUST_PROXY` | `1`, если сайт стоит за nginx, Caddy или Traefik |
| `ALLOW_ORG_SIGNUP` / `ALLOW_INDIVIDUAL_SIGNUP` | разрешить создание компаний / регистрацию без кода |
| `SESSION_DAYS` | срок жизни сессии |
| `REVIEW_DELAY_HOURS` | через сколько вернуть вопрос, в котором ошиблись (по умолчанию 48) |
| `MIN_GROUP` | минимум людей для показа сводки ошибок |

## 👥 Как это работает для людей

Регистрация предлагает три пути. Везде указываются имя, фамилия и пол: по имени обращается Черепундель, а пол определяет иллюстрации в сюжетах.

| Путь | Что получается |
|---|---|
| 🏢 **Новая компания** | Создаётся компания и её администратор, задаются подразделения. Администратор получает **код компании** |
| 🙋 **Я сотрудник** | Сотрудник вводит код компании, выбирает подразделение и попадает в свою организацию |
| 🧑‍🎓 **Учусь сам** | Человек без компании. Уровни, награды и сертификат работают так же |

Всё, что человек заработал (звёзды, очки, уровень, бейджи, серия дней, точность по темам, сертификат), хранится в базе и привязано к аккаунту.

### Правила игры

- **Урок.** Доверие отдела начинается со 100%, за каждую ошибку −20%. Урок засчитывается при 60% и выше и если верно не меньше половины ответов.
- **Звёзды.** 1 за прохождение, ещё 1 при доверии от 90%. Если прошли хуже, повторите урок: недостающая звезда начислится.
- **Вопрос дня.** 1 звезда и 20 очков за верный ответ. Вопросов 14, они сменяются по дням.
- **Уровни.** Пороги 0, 3, 7, 12, 18, 25, 33, 42 звезды. Недели 1 и 2 открыты сразу, неделя N (с 3-й) открывается на уровне N.
- **Повторение ошибок.** Открывается на уровне 2: вопросы с ошибками возвращаются через 48 часов.
- **Экзамен.** Уровень 8, 14 случайных вопросов (по 2 из каждой недели), нужно 80%, без подсказок. Даёт 2 звезды, 200 очков и сертификат с публичной страницей `/certificate/<номер>`.
- **Серия дней** считается по часовому поясу человека.

## 🛠 Кабинет администратора

Кнопка «Для администратора» видна только админам компании.

- **Обзор:** прогресс по подразделениям, темы с частыми ошибками, прохождение каждой недели, активность за 14 дней
- **Сотрудники:** прогресс, подразделение, роль, отключение, **сброс пароля** (временный пароль виден один раз, при входе сотрудник придумывает свой), выгрузка CSV для Excel
- **Подразделения:** добавить, переименовать, удалить
- **Настройки:** код приглашения (можно выпустить новый), разрешённый домен почты, режим открытия недель

**Режим открытия недель.** «По уровням» это игровая механика. Для обязательного обучения со сроком включите «По порядку»: следующая неделя открывается после предыдущей, а экзамен после всех семи.

**Приватность заложена в устройство.** Администратор не видит ответы и ошибки конкретных людей. Сводка ошибок показывается по темам и только если ответили минимум 3 человека. Командный зачёт считает очки подразделений, а не людей.

## ✏️ Как менять курс

Весь контент лежит в `backend/content/course.json`: недели, уроки, главы, материалы, вопросы, вопросы дня.

Типы вопросов: `one` (один ответ), `tf` (верно/неверно), `multi` (несколько), `sort` («можно/нельзя» для каждого пункта). Правильный ответ: число для `one` и `tf`, список номеров для `multi`, список 0/1 для `sort`.

Чтобы добавить сюжет, создайте в нужной неделе урок с ключом `неделя.номер` (например `3.3`) и главой со структурой `intro`, `story`, `cards`, `questions`, `material`. Для иллюстрации по полу добавьте в главу поле `scene` с путями `f` и `m`. Ключ урока после запуска **не меняйте**: по нему записан прогресс людей. После правки перезапустите сервер.

## 🔐 Безопасность

Пароли хэшируются (scrypt). Сессия лежит в HttpOnly-cookie (SameSite=Lax), на сервере хранится только хэш токена. Число неудачных попыток входа и регистраций с одного адреса ограничено. Запросы с чужого Origin отклоняются, пользовательские данные экранируются при выводе. Администратор не может отключить последнего админа и работает только в своей компании.

**Что учесть при выходе в продакшен**

- Поставьте перед сервисом HTTPS (nginx, Caddy, Traefik) и задайте `COOKIE_SECURE=1`.
- Восстановления пароля по почте нет: пароль сбрасывает администратор или `python manage.py reset-password`.
- Шрифт Onest подключается с Google Fonts. Без интернета подставится системный.
- SQLite выдерживает сотни одновременных сотрудников. Для тысяч и нескольких серверов лучше PostgreSQL.
- Делайте резервные копии `data/academy.db`.

## 🤝 Участие в разработке

1. Заберите свежий код: `git pull`
2. Создайте ветку под задачу: `git checkout -b fix-login`
3. Внесите изменения и проверьте тесты
4. Отправьте ветку: `git push -u origin fix-login`
5. Откройте **Pull Request** на GitHub, после проверки он вливается в `main`

Не добавляйте в репозиторий файл `.env`, папку `data/` и реальные данные сотрудников.
